Chat backend built for 10 million connections

Backend & systems. Stateless gateways, Kafka fan-out and end-to-end encryption.

A production-style messaging backend designed to hold up to 10 million concurrent users. Messaging looks simple until you ask it to serve millions of people at once. Connections have to stay open, messages must never be lost when someone is offline, group chats multiply every message, and the content has to stay private.

How it works

  • Stateless WebSocket gateways hold the persistent connections, so any gateway can be added or removed without losing state.
  • Services split by job: chat, groups, users, presence, receipts, offline sync, crypto keys and media.
  • Each kind of data lives where it fits: Redis for ephemeral state, Cassandra for messages, PostgreSQL for users and S3 for media.
  • Kafka fans group messages out asynchronously so one busy group cannot stall everyone else.
  • End-to-end encryption uses Signal Protocol style key management; media goes through pre-signed S3 URLs.

What I learned: Choosing the right store for each kind of data matters more than choosing one great database.

Built with Distributed systems, Kafka, Redis, Cassandra, WebSockets, E2E encryption. Code on GitHub

The Traffic Jam: an observability lab

Backend & systems. Nginx, Prometheus, Grafana and k6 in one Docker Compose command.

A small, complete stack that shows how a service behaves under load, and how to see it happening. It is easy to read about load balancers and dashboards. It is harder to feel what happens when CPU-heavy requests pile up. This project makes that visible.

How it works

  • A Node.js service with a health route, a heavy route that pushes CPU work into worker threads, and a metrics route.
  • Nginx sits in front as a reverse proxy and load balancer using least-connections, and keeps the metrics route private.
  • Prometheus scrapes custom metrics (including a gauge of active workers) and Grafana turns them into dashboards.
  • k6 generates 50 virtual users of load for 30 seconds so the graphs have something to show.
  • Everything starts with one Docker Compose command.

What I learned: You only trust a system you can watch. Metrics first, then tuning.

Built with Observability, Docker, Nginx, Prometheus, Grafana, k6. Code on GitHub

Credit card fraud detection

Machine learning. A logistic regression model that spots fraudulent transactions.

A model that predicts whether a card transaction is fraud, trained on a dataset of almost 3 lakh transactions.

How it works

  • Load the dataset and check for missing values.
  • Count the labels: legitimate transactions outnumber fraud by about 99 to 1.
  • Compare the two groups and build a balanced sample with a similar distribution.
  • Split the data 80/20, keeping the label ratio the same in both halves.
  • Train a logistic regression model and check training and test accuracy: 92% and 90%.

What I learned: On unbalanced data, accuracy can lie. Always compare training and test scores to catch overfitting.

Built with Python, scikit-learn, pandas. Code on GitHub

Fake news detection

Machine learning. A logistic regression model that flags fake news.

A text classifier that learns what fake and real articles look like and labels new ones.

How it works

  • Download English stop words with NLTK.
  • Fill missing values and merge the author and title.
  • Stem every word to its root, remove non-letters, lowercase and drop stop words.
  • Vectorise the text, turning words into numbers.
  • Split into train and test and fit a logistic regression.
  • Check accuracy on both halves and predict a new article.

What I learned: Models read numbers, not sentences. Most of the craft is how the text becomes numbers.

Built with Python, NLTK, scikit-learn. Code on GitHub
