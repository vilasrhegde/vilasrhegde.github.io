$ cat principles.md # how I think

  1. Do it by hand once, automate it the second time. If a task comes back, it gets a script. The first time teaches me what the script should do.
  2. Plan for the bad day. I design for the user who is offline, the retry that arrives twice and the server that dies mid-request.
  3. Measure before arguing. A graph ends most debates faster than an opinion does.
  4. Write it down before building it. A one-page design doc saves a week of rework and lets others build without waiting on me.
  5. Unblock people first. My own task can wait an hour. A teammate stuck for a day costs more.
